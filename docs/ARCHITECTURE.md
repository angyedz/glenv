# glenv architecture

glenv runs two userspace systems side by side on one Alpine machine: musl
(the host, untouched) and glibc (a full Debian trixie userspace kept inside
`/opt/glibc-env`). No chroot, no container — routing happens at the ELF level.

## Directory layout

```
/opt/glibc-env/
├── bin/glenv                  router (Go): run, doctor, desktop, tui
├── lib/glenv-wayland-filter.so  Wayland explicit-sync filter (preloaded)
├── sysroot/                   the Debian userspace root
│   └── usr/{bin,lib,...}      glibc 2.41, GTK, Mesa, PipeWire, curl...
├── debs/                      downloaded .deb cache + Packages index
├── src/                       sources (glenv router, wayland shim)
├── tools/                     integrate-system, fetch-deps, wrappers
└── install.sh                 the installer
```

## Routing: the kernel picks the loader from PT_INTERP

Every ELF binary names its interpreter in the header. Debian glibc binaries
say `/lib64/ld-linux-x86-64.so.2`; musl binaries say `/lib/ld-musl-x86_64.so.1`.
The kernel loads that interpreter at `execve` — so if the glibc loader is
installed at its expected path and `ld.so.cache` points into the prefix, a
Debian binary runs **directly**, with no wrapper, no flags and no environment
voodoo:

```
./DebianBinary
 └─ kernel reads PT_INTERP → /lib64/ld-linux-x86-64.so.2  (symlink)
     └─ /lib/ld-linux-x86-64.so.2  (real glibc loader, from sysroot)
         └─ /etc/ld.so.cache  → search paths under /opt/glibc-env/sysroot
             └─ libc, libGL, libpipewire... resolve inside the prefix
```

musl binaries never see any of this: musl ignores `/etc/ld.so.cache` and
`/etc/ld.so.preload` — those two files are glibc-only, which is why glenv can
use them freely on a musl host.

`glenv` itself (the Go router) is musl-linked and provides policy on top of
direct exec: `glenv run --sandbox=... --as=...` (namespaces, uid mapping),
`glenv doctor` (diagnostics), `.desktop` integration.

## Bind mounts: the only shared paths

Seven mount points make Debian *paths* exist on the Alpine filesystem, so
glibc binaries that open well-known locations (`/usr/lib/x86_64-linux-gnu`,
`/usr/share/i18n`, ...) find their files. All mounts are `bind`, recorded in
`/etc/fstab` (so they survive reboots), and all sources live inside the
prefix:

| Mount point | Source |
|---|---|
| `/usr/lib/x86_64-linux-gnu` | `$PREFIX/sysroot/usr/lib/x86_64-linux-gnu` |
| `/lib/x86_64-linux-gnu` | `$PREFIX/sysroot/lib/x86_64-linux-gnu` |
| `/usr/lib64` | `$PREFIX/sysroot/usr/lib64` |
| `/usr/lib/locale` | `$PREFIX/sysroot/usr/lib/locale` |
| `/usr/share/i18n` | `$PREFIX/sysroot/usr/share/i18n` |
| `/usr/share/glvnd` | `$PREFIX/sysroot/usr/share/glvnd` |
| `/usr/share/drirc.d` | `$PREFIX/sysroot/usr/share/drirc.d` |

They are regular directories on musl (mostly empty), and unmounting them —
which `--uninstall` does — returns the system to its original state. The
directories themselves are only removed when empty.

## System integration files (and their removal)

| File | Install | Uninstall |
|---|---|---|
| `/lib/ld-linux-x86-64.so.2` | real glibc loader; a pre-existing one (gcompat) is kept as `*.gcompat-shim` | shim restored if present, otherwise removed |
| `/lib64/ld-linux-x86-64.so.2` | symlink → `../lib/ld-linux-x86-64.so.2` (Debian PT_INTERP) | removed if it is exactly ours |
| `/etc/ld.so.cache` | generated by the glibc `ldconfig` from the sysroot | deleted (musl does not use it) |
| `/etc/ld.so.conf.d/glibc-env.conf` | include path into the prefix | deleted |
| `/etc/fstab` | 7 bind-mount lines | only the lines whose source starts with `$PREFIX` |
| `/etc/ld.so.preload` | wayland filter `.so` (our line added) | only our line removed; foreign lines kept |
| `/etc/profile.d/glibc-env.sh` | puts `$PREFIX/bin` into PATH | deleted |
| `/usr/local/bin/glenv` | symlink → `$PREFIX/bin/glenv` | deleted (only if a symlink) |

## ldconfig: which binary generates the cache

Alpine's `ldconfig` is BusyBox: it exits 0 without doing anything useful for
glibc caches. glenv always runs **the Debian one from the sysroot**
(`$SYS/usr/sbin/ldconfig`), which is why `ld.so.cache` gets real entries
(hundreds) and glibc binaries resolve their libraries. The same trap applies
to `verify`: an honest check must look at the cache size/entries, not at the
exit code.

## Wayland filter

See the README section "Wayland: explicit sync without fences would freeze
the frame". Summary: `lib/glenv-wayland-filter.so` is preloaded for all glibc
programs via `/etc/ld.so.preload`, interposes `recvmsg()` on the Wayland
socket, and rewrites the `wp_linux_drm_syncobj_manager_v1` interface name
(equal-length decoy, framing-preserving) so clients fall back to
`wl_buffer.release` based rendering instead of waiting forever for fences
this GL stack cannot produce.

## Rebuilds

```sh
cd src/glenv && go build -o ../../bin/glenv .
gcc -shared -fPIC -O2 -nostdlib -o lib/glenv-wayland-filter.so \
    src/shim/glenv-wayland-filter.c
```

`install.sh` builds from source when `go`/`gcc` are present and otherwise
uses the committed prebuilts, so a target machine needs no toolchain.
